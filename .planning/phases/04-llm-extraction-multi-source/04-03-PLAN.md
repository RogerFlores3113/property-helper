<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user POST → ARQ coordinator | Enqueue target string is a fixed literal `"run_search_coordinator"`; user cannot influence which function runs |
| coordinator → sub-task enqueue | Sub-task names are computed from the in-process `ENABLED_SOURCES` literal list, not from user input |
| sub-task → search_jobs.status | Only mark_done writes status; sub-task body cannot directly flip terminal state (D-15) |
| Redis counter keys (expected/completed/failed) | Private cluster Redis with 1h TTL; key namespace is `{counter}:{job_id}` where job_id is UUID-format |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-06 | Tampering | Redis counter keys | mitigate | Keys are `expected:{job_id}`, `completed:{job_id}`, `failed:{job_id}` where job_id is a server-issued UUID; never reflects user input. TTL ex=3600. |
| Status race / double-flip | Integrity | mark_done UPDATE | mitigate | UPDATE guarded by `WHERE id=$1 AND status='running'` — only the first crossing of `completed >= expected` flips. Idempotent on subsequent calls. |
| Stuck-running on coordinator early-return | Availability | run_search_coordinator | mitigate | Coordinator does NOT own terminal status (Pitfall 5); sub-tasks drive completion via mark_done. Frontend's existing Realtime subscribe to search_jobs UPDATE handles the eventual flip. |
| Inline jitter race across workers | Integrity (SCRAP-04 violation) | craigslist.py fetches | mitigate | Inline `asyncio.sleep` removed; `acquire_domain_slot` is the only path to a Craigslist fetch. Per-process Semaphore would not coordinate across Fly Machines; Redis SET NX PX does. |
</threat_model>
